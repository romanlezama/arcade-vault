## Project

Arcade Vault is an online platform for playing games and competing for the highest score. It is at the very start: the codebase is still the `create-next-app` scaffold (`app/layout.tsx`, `app/page.tsx`, `app/globals.css`), so most of the product has yet to be built.

Development follows **Spec Driven Design** with the `/spec` (write a spec) and `/spec-impl` (implement a spec) skills from [Klerith/fernando-skills](https://github.com/Klerith/fernando-skills), installed with:

```bash
npx skills@latest add Klerith/fernando-skills
```

When adding a feature, prefer writing or updating a spec first and implementing from it. The README and specs are written in Spanish.

## Commands

```bash
npm run dev     # next dev (Turbopack), http://localhost:3000
npm run build   # production build; also type-checks
npm run start   # serve the production build
npm run lint    # ESLint 9 flat config (next core-web-vitals + typescript)
npx tsc --noEmit  # type-check only
```

No test framework is configured yet.

## Stack and non-default configuration

- **Next.js 16.4 (App Router only), React 19.3, TypeScript strict.** Next.js APIs differ from older versions; check `node_modules/next/dist/docs/` (`01-app/` for App Router) before using any Next API.
- **`cacheComponents: true` + `partialPrefetching: true`** (`next.config.ts`): data fetching is dynamic by default and caching is opt-in via the `use cache` directive with `cacheLife` / `cacheTag`. Uncached dynamic data must sit inside a `<Suspense>` boundary so the static shell can prerender. Do not add `runtime` route segment exports (unsupported with Cache Components), and don't use legacy `export const revalidate`/`dynamic` patterns without checking the docs (`01-app/guides/migrating-to-cache-components.md`).
- **`experimental.agentFeedback: true`**: `next dev` rewrites the managed block in `AGENTS.md`; commit that block rather than reverting it.
- **Tailwind CSS v4** is loaded through a custom Turbopack loader rule (`@tailwindcss/turbopack` for `*.css`), not PostCSS — there is no `postcss.config` or `tailwind.config`. Theme tokens are defined in `app/globals.css` via `@theme inline` and CSS variables (light/dark via `prefers-color-scheme`).
- Typed route helpers like `LayoutProps<"/">` / `PageProps<...>` are global types generated by Next (see `next-env.d.ts`, `.next/types`).
- Import alias: `@/*` maps to the repo root.
